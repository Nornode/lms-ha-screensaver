# Lyrion Music Server (LMS) Plugin Development Skill

Use this skill whenever creating, modifying, or debugging Perl code under `server-plugin/HAScreenSaver/`.

## 1. Plugin Directory Layout

```text
server-plugin/HAScreenSaver/
├── install.xml                  # LMS plugin manifest (minVersion 8.0, maxVersion *)
├── strings.txt                  # Localization tokens (tab-separated, EN required)
├── Plugin.pm                    # Main module: initPlugin, RPC dispatch, HA proxy, repo server
├── Settings.pm                  # Slim::Web::Settings subclass for LMS Web UI
├── AppletDist/                  # Generated by scripts/build.sh (gitignored .zip/.sha1)
└── HTML/EN/plugins/HAScreenSaver/settings/
    └── basic.html               # Template Toolkit settings page
```

## 2. Non-Blocking Async HTTP (Zero-Cache Rule)

LMS runs a single-threaded AnyEvent I/O loop. Blocking HTTP calls freeze audio playback and UI responsiveness across all players.

- Always use `Slim::Networking::SimpleAsyncHTTP->new(\&on_ok, \&on_err, { cache => 0, timeout => 5 })`.
- Always pass `'Cache-Control' => 'no-cache'` and `'Authorization' => "Bearer $token"` headers.
- Never write fetched sensor states to `Slim::Utils::Cache`, prefs, or disk.

## 3. Home Assistant Authentication Modes

1. **Home Assistant Add-on Mode (Auto)**:
   When LMS runs inside a Home Assistant add-on with `homeassistant_api: true` (such as `pssc/ha-addon-lms`), `$ENV{SUPERVISOR_TOKEN}` is automatically injected into the container environment.
   - Base URL: `http://supervisor/core`
   - Endpoint: `http://supervisor/core/api/states/<entity_id>`
   - Header: `Authorization: Bearer $ENV{SUPERVISOR_TOKEN}`
2. **Standalone / Custom Mode**:
   When a custom HA URL and Long-Lived Access Token are configured in LMS Settings, use `<ha_url>/api/states/<entity_id>` with the configured token.

## 4. Registering Comet / JSON-RPC Commands

Register player-scoped commands in `initPlugin`:

```perl
Slim::Control::Request::addDispatch(
    ['hascreensaver', 'sensors'],
    [1, 1, 0, \&handleSensorsRequest]
);
```

- First flag `1` = requires a player (`$client`) when called by a player (still works with `""` for server-level CLI/JSON-RPC testing if you guard `my $client = $request->client();`).
- Second flag `1` = query (read-only).
- Because HA HTTP calls are asynchronous, call `$request->setStatusProcessing()` before returning from `handleSensorsRequest`, and call `$request->setStatusDone()` inside the final async callback.

## 5. Inspecting Radio Alarm Status

When `$client` is present, check whether an alarm is scheduled on that specific player:

```perl
my $nextAlarm = eval { Slim::Utils::Alarm->getNextAlarm($client) };
```

If `$nextAlarm` is defined, extract its formatted time (e.g. `HH:MM`) and set `alarm_active => 1` in the response.

## 6. Instant Refresh Notifications (Event-Driven Push)

Register a lightweight trigger command `['hascreensaver', 'refresh']` that broadcasts `Slim::Control::Request::notifyFromArray(undef, ['hascreensaver', 'refresh'])`. Any Home Assistant automation (e.g. door contact opened) can call the LMS JSON-RPC endpoint with `["", ["hascreensaver", "refresh"]]` to prompt active radios to re-fetch immediately without waiting for the 60s poll timer.

## 7. Self-Hosting the Radio Applet Repository

Use `Slim::Web::Pages->addPageFunction` (with handler signature `($client, $params, $callback, $httpClient, $response)`) to serve:
- `plugins/HAScreenSaver/repo.xml` — dynamically uses `$params->{host}` so `url="http://<lms-host>:9000/plugins/HAScreenSaver/HAScreenSaver.zip"` always matches the local LAN address, with the live SHA-1 hash of the packaged zip.
- `plugins/HAScreenSaver/HAScreenSaver.zip` — streams the zip from `AppletDist/HAScreenSaver.zip` with `application/zip` content type.

## 8. Local Verification

Always run the local test suite before deploying:
```bash
./scripts/test.sh
```
